# AAB助手

本次交付文件夹：`aab自动打包软件1`（为避免覆盖已有同名文件）。主应用：`AAB助手.app`。采用深蓝色横向操作台。

基于 Partner Agent 0.1.21 整理的免登录桌面版。主要用于在本机检查 Android 工程、处理构建问题，并在编译通过和用户确认后生成 Release AAB。保留原有 SDK 接入、数据同步和网站生成模块。

**本交付包为 macOS 版，不含可运行的 Windows 版本。** AAB 格式并不限于 Mac；限制来自这份软件当前携带的运行组件和平台实现。

## 从哪里开始

1. 将 `AAB助手.app` 拖入“应用程序”。
2. 双击打开；若因下载隔离标记不能启动，保存工作、退出主应用，再运行同包的 `修复 AAB助手 启动.app`。
3. 按[使用教程](USER_GUIDE.md)配置自己的模型服务，选择 Android 工程，编译后确认生成 AAB。

**在终端直接运行一次修复脚本：** 输入 `/bin/sh`，加空格，拖入 `partner-agent-fix.sh`；再加空格，拖入目标 `AAB助手.app`，按回车。完成后直接双击主应用。详细步骤见[使用教程](USER_GUIDE.md)的“在终端直接运行一次修复脚本”一节，所有路径通过拖入文件自动填写。

包内包括主应用、可双击运行的修复应用、备用修复脚本、README、使用教程及搭建实现简介。无需软件账号；模型服务、Unity 或 Apple 开发者工具仍按各自要求配置。

## 系统与工程要求

- 当前主程序和模型执行引擎为 Intel x86_64 的 macOS 二进制；以 macOS 13 或以上为使用基线。Apple 芯片 Mac 需 Rosetta 2，此交付未完成所有机型的实机验收。
- GP打包接收完整 Android Gradle 工程。Unity 游戏须提供 Android 导出工程，其中包含 `settings.gradle`、`launcher` 和 `unityLibrary`；不能将任意文件、APK 或 AAB 直接变成新 AAB。
- 需要匹配工程的 JDK、Android SDK、签名材料及网络。AI 检查和修复需要用户自己的模型 API 配置，费用由对应服务提供方收取。
- 游戏预处理可能修改所选原工程，并为部分配置保留备份；开始前请完整备份交付目录及签名文件。

## 为什么当前版本不能直接运行在 Windows

1. **应用外壳不是 Windows 程序。** 本包 `.app` 中的 Electron 是 Mach-O x86_64 格式，不能由 Windows 加载。改扩展名为 `.exe` 不会转换可执行格式。
2. **模型引擎也是 Mac 二进制。** 内置文件虽然名为 `opencode.exe`，实际格式仍是 Mach-O，需要替换成匹配版本的 Windows 引擎。
3. **桌面和工具链入口依赖 macOS。** 当前启动器使用 Mac 应用路径和 shell 包装；目录选择使用 `osascript`，游戏 JDK、SDK、NDK 准备逻辑使用 Mac 路径、命令与下载资源。普通 Android 的 Gradle 调用已有 Windows 分支，但这些关键环节尚未整体适配。
4. **内置 Unity 编译资源不能跨系统复用。** GP 游戏资源清单声明 `mac-intel`，附带的是 macOS IL2CPP deploy。Windows 需要与工程 Unity 版本及导出结构匹配的 Windows IL2CPP 工具，不能把 Mac deploy 直接放进 Windows 工程运行。现有材料未提供经过核对的配套 Windows 游戏资源。
5. **全部功能无法在 Windows 上本地实现同等构建能力。** 软件保留 iOS SDK 接入及交付流程，最终 iOS 构建、签名和设备交付依赖 macOS/Xcode；即使完成 Windows AAB 版，这部分仍需要 Mac 或连接 Mac 构建机。

上述结论依据现有程序与资源检查，不表示 Android AAB 无法在 Windows 生成。要推出 Windows AAB 版，需要替换桌面及模型运行组件、适配路径与进程管理、文件选择及 JDK/SDK 工具链，准备匹配的 Windows Unity 导出资源，再用真实 Windows 工程验证编译、签名、取消、恢复和 AAB 输出。开发环境目前没有完成 Windows 实机验收，因此本包不将任何 Windows 预览组件作为成品分发。

## 新界面怎么用

- 顶部横向导航切换原有功能模块，右侧保留设置入口。
- “GP打包”页面上方为工程、应用类型和版本配置；“开始编译”位于标题右侧。
- 下方左侧是打包记录，可切换历史任务或新建打包；右侧是进度、对话、构建日志和产出文件。
- 编译通过后，标题右侧出现“确认打包”和“取消打包”。确认规则、参数、消息处理和产物下载保持原有流程。

## 发给另一台电脑

完整发送本文件夹的 ZIP，接收方解压后使用。文件夹可以放在桌面、下载或其他可写目录，不要求与制作电脑使用相同用户名或位置。

内部运行程序、模块和资源按应用自身位置查找；个人数据按当前用户目录创建，不包含制作电脑的模型密钥、项目路径或任务记录。修复工具优先查找同文件夹的 `AAB助手.app`，再查找系统和当前用户的“应用程序”；找不到时可手动选择。备用脚本也支持传入目标 App 路径。

目标工程、签名文件及外部 JDK/SDK 由接收方在自己的电脑上准备和选择。已有任务中记录的工程路径属于该任务所在电脑，复制个人数据不等于自动迁移工程；换电脑后请重新选择工程并配置模型。

## 数据、更新与分发

本机数据目录继续使用 `~/Library/Application Support/Partner Agent Public/`，改名不改变已存在的公开版数据位置。原先需要登录的版本使用另一数据目录；本包不自动迁移它的记录。

旧版更新安装通道保持停用，后续使用新的公开版安装包更新。应用已做本地临时签名，未做 Apple 开发者签名和公证。修复工具只清除指定主应用的下载隔离标记，不会关闭整个系统的 Gatekeeper；它不替代正式签名、公证或应用来源核验。
