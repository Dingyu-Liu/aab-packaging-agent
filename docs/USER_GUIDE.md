# AAB助手使用教程

## 一、安装

1. 解压 `aab自动打包软件.zip`，打开其中的同名文件夹。
2. 将 `AAB助手.app` 拖到 Finder 的“应用程序”文件夹；更新已有版本前先保存工作并退出主应用。
3. 双击“应用程序”中的 `AAB助手`。打开后直接进入工作台，无需软件账号或密码。
4. 当前仅提供 macOS 安装包。Windows 不能运行 `.app`，具体原因见 [发行说明](DISTRIBUTION_README.md)。Apple 芯片 Mac 若提示需要 Rosetta，按系统提示处理后重试。

## 二、下载后打不开时

如果 macOS 因下载隔离标记阻止启动：

1. 保存工作并退出主应用。
2. 双击同包的 `修复 AAB助手 启动.app`。它优先查找自己旁边的主应用，再查找系统“应用程序”和当前用户的“应用程序”目录；找不到时提示选择应用。
3. 工具只清除所选应用及其内部文件的下载隔离标记，然后尝试打开主应用。它不会关闭系统整体安全设置。
4. 如果存在多份主应用，将修复工具放在要修复的那一份旁边，或使用下述备用脚本明确指定目标。

若修复应用本身也被拦截，可按系统“隐私与安全性”中的允许打开提示处理；或打开“终端”，输入 `/bin/sh `（末尾有空格），将同包的 `partner-agent-fix.sh` 拖入终端，再回车。

脚本会自动寻找同目录、系统“应用程序”或当前用户“应用程序”里的主应用。也可在脚本路径后加一个空格，再将目标 `.app` 拖入终端，明确选择任意位置的应用。不要照抄别人的 `/Users/用户名/...` 路径。

“无需修复”表示应用及内部文件没有隔离标记；“找不到应用”时确认应用已经解压且名称正确；“清除失败”时检查目标目录写入权限。隔离修复不能解决文件损坏、缺少 Rosetta 或系统版本不兼容。

## 三、首次配置模型

1. 点击顶部横向导航或右上角的“设置”，填写自己的模型 API 地址、协议、模型名称及 API Key。
2. 使用支持工具调用的模型，按页面提供的连接测试或发一条简单消息检查连接。
3. 如果提示连接失败，核对地址、密钥、余额/额度、网络及代理；不要把密钥发到聊天记录、公共项目或交付包。
4. 仅取消了本软件登录，模型接口并不因此免费或免密钥。

## 四、准备工程与签名

1. 先备份完整工程和原签名文件，建议使用版本管理。GP 流程直接在所选工程处理构建问题，部分配置修改会留下备份，但不能替代完整备份。
2. 普通 Android：选择包含 `settings.gradle` 或相应 Kotlin 配置、Gradle Wrapper 及应用模块的工程根目录。
3. Unity 游戏：先取得 Android 导出工程。选择完整交付目录，确保其中有 `launcher`、`unityLibrary`、`settings.gradle`，以及该应用原有 `.jks` / `.keystore` 和签名配置。签名若在工程上一级，就选择同时包含工程与签名的父目录。
4. 一个交付目录最好只放本次目标工程；多个工程或多个可用密钥时，根据提示明确选择。
5. 检查磁盘空间和网络，准备项目要求的 JDK、SDK/NDK 等环境。游戏固定预处理涉及 Android Platform 36、Build Tools 36.1.0、NDK 29.0.14206865 和内置 Mac IL2CPP；若工程与模板不兼容，应按实际诊断处理，不能认为任意 Unity 版本都已验证。
6. 更新已经发布的应用必须保留原签名。不要用新密钥替代原签名来处理构建失败。

## 五、编译并生成 AAB

1. 点击顶部横向导航的“GP打包”，选择“游戏”或“其他”应用类型。
2. 选择工程/交付目录，填写目标版本号与 Version Code；例如版本号 `1.0.1`。发布更新时 Version Code 应大于已有版本。
3. 若工程有多个应用模块或 Release 变体，展开配置面板下方的“构建选项”，填写本次目标。
4. 点击页面标题右侧的“开始编译”。程序检查环境、读取工程、执行预处理并收集 Gradle 日志；需要 AI 修复时使用已配置的模型。
5. 如果提示缺少签名、依赖、网络或其他输入，处理提示中明确的问题，在原任务中补充信息或继续。
6. 编译通过后，页面标题右侧显示“确认打包”和“取消打包”；核对信息后点击“确认打包”生成 Release AAB。工程内容变化后，需重新验证编译状态。
7. 点击右侧工作区的“产出文件”下载 AAB，核对版本、签名和日志。工具生成 AAB 不等于已上传 Google Play；发布仍需按商店流程完成检查与提交。

左侧“打包记录”可以切换和继续历史任务；“新建打包”进入新任务。右侧“大模型对话”补充要求，“构建日志”查看实际编译信息，“产出文件”查看下载结果。运行时停止按钮仍在工作区标题旁。

## 六、常见问题

- **找不到工程：** 选择源码/导出工程目录，不是 APK、AAB、单个文件或未解压的压缩包。
- **Unity 游戏识别失败：** 核对是否为包含 `launcher` 与 `unityLibrary` 的 Android 导出工程，原始 Unity `Assets` 目录不等同于 Android 导出工程。
- **模型连接中断：** 先修复连接配置，再在原会话继续；以实际任务状态为准。
- **编译长时间无输出：** 查看日志区分依赖下载、原生编译和错误。需要停止时使用任务取消操作。
- **签名失败：** 核对原文件、密码、alias 与工程配置；不要另建密钥替代原签名。
- **Windows 打不开：** 当前交付是 Mac 程序，不提供 Windows 可执行文件；参阅 README 的平台说明。

## 七、换一台电脑使用

发送完整的 `aab自动打包软件.zip`，对方解压并安装。若外层文件夹为避免重名带有数字后缀，操作方法不变。软件不会要求制作电脑上的目录或用户名；应用可换位置，修复工具可自动查找或手动选择目标。

在新电脑重新配置自己的模型服务、选择实际工程目录，并准备所需 JDK/SDK 和原签名。主应用包不携带个人运行数据；需要历史记录时应另行迁移数据目录，且重新检查工程、签名、工具链路径。

## 八、记录与问题定位

在 Finder 的“前往文件夹”输入 `~/Library/Application Support/Partner Agent Public/`。
`logs/desktop.log` 是桌面启动日志，任务记录和相关构建日志由本地服务保存在数据目录中。改名为“AAB助手”后仍沿用该公开版目录。分享日志前移除密钥、签名密码及项目敏感信息。

本交付未以用户真实工程完成 AAB 构建验收。第一次使用应先在备份工程上检查完整流程。
