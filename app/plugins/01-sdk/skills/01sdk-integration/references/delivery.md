# 自动测试隔离与交付收尾

适用于需要真机验证、交付 Unity 工程或把普通测试包留在用户手机上的任务。只阅读 Demo 的任务不因此扩大为构建、安装或联网测试。

## 同时维护三个版本事实

| 对象 | 记录 / 验证 |
|---|---|
| 当前工程 | 唯一源目录绝对路径、已保留的用户改动、运行代码与 SDK 配置的差异/哈希 |
| 交付 ZIP | 从该源目录打包，保留 Assets/Packages/ProjectSettings、资源和 .meta、SDK 许可；逐文件对比和 CRC；排除本次临时运行测试器与缓存，保留项目需要的 Editor 回归测试 |
| 手机已安装包 | QA 或普通包、Bundle ID、构建版本/产物哈希、安装与启动记录、当前运行时间，以及普通包冷启动结果 |

**源码干净、ZIP 干净和手机干净是三项独立结论。** 用户说“测试没问题，发工程”不证明手机已切回普通包。安装包检查脚本也不能证明设备现在运行的就是这个包。源码/ZIP 修正并升构建号后，若未重新安装，分别记录交付构建与手机旧构建，不把签名构建通过写成手机修复已生效。

使用 `../assets/integration-inputs.example.json` 的 project/h5/delivery 项记录目标和收尾状态。中断/切换对话后先核对当前安装包类型和未完成的收尾；不要根据一份旧 passed 报告默认交付已完成。用户取消任务时停止操作并准确说明实际残留状态；恢复工作后再继续收尾。

方向也是这三份产物分别核对的内容：源工程保留游戏原方向，App 启动与默认网页按 01 默认使用 Portrait，随包配置独立保留游戏原契约，ZIP 与实际构建源码一致。普通包验证应包含竖屏 Loading/网页与回退游戏的原方向；不能因为游戏本身横屏就接受普通启动/网页横屏，也不能把回退游戏强制成竖屏。实现及证据项见 [启动方向](startup-presentation.md#按阶段控制方向)。

## 自动 QA 的边界

优先用本次显式运行的外部驱动调用网页接口。必须把测试器编入专用 QA 包时，使用独立编译条件，并且在创建常驻对象前检查显式启动标记；采用有持久证据的一次性 runId 消费机制，防止重启复跑。普通包不带测试器。仅设置 Development Build 或一个测试编译符号，不构成“只运行一次”。

特别检查 `RuntimeInitializeOnLoadMethod`、`AfterSceneLoad`、`Awake/Start`、编辑器轮询器、恢复到前台回调、H5 autorun 参数。不能让普通启动自动：

- 加载本地测试网页或绕过正式入口。
- 发起旋转序列、颜色对照、自动桥接用例。
- 发送 AF/FB 测试事件或注入测试回调。

测试器将背景暂改白色、强制左右横屏、覆盖 `window.onUnityMessage`，都是会改变用户所见画面的干预。测试前记录这些干预；出现闪白/自动旋转时优先查测试器和本次记录，不能直接归因给 SDK。恢复黑色、恢复方向或运行结束的 `completed=true` 只能清理本轮，不能阻止下一次冷启动重新创建测试器。不要通过透明、遮挡、裁掉安全区等方式隐藏测试器造成的现象。

Facebook 临时详细日志也要收尾：保存原始 `FacebookLoggingBehavior`/诊断设置，只恢复本次增加的项目，再核对实际安装普通包的配置与冷启动输出。不能只改回源配置却把详细日志包留在手机上。具体取证见 [FB 排查](facebook-events.md)。

## 普通包收尾顺序

本任务或已授权的前序测试曾把 QA 包安装到用户手机时，在当前授权仍包含设备操作的范围内换回普通包；仅交付源码不代表已完成手机收尾。用户明确自行测试或暂停设备操作后，停止后续安装、终止/重启应用和自动点击，保留当前状态；若 QA 包尚未恢复，准确报告该残留，不以默认收尾为由继续操作。用户只暂停打包时暂停归档，仍按其明确要求继续独立的源码修复。若整个任务从未涉及设备，只做源码/归档交付，不因此新增安装；用户明确要求保留专用 QA 包时，记录该选择及自动行为，不标为普通包交付。

1. 保存 QA 证据与测试器来源，记录自动操作、开始/结束时间及复跑条件。
2. 先对比 Unity 源插件、导出插件与 QA 差异，把需要保留的功能修复落实到源码/可重现的导出流程。**本次普通包要使用的导出副本必须先清除 QA 干预，再构建**：去除自建自动测试器、QA 编译定义、原生截图/对照插件、autorun 入口；保留真实 SDK、正常 H5 旋转指令和已验证别名。不要把“恢复”理解为回滚所有改动，也不要只在手机内临时关闭一个对象。
3. 完成该普通包的编译、链接、签名、包名/配置核对。扫描实际 IL2CPP 元数据和原生二进制中本项目已知的测试类/符号；不能只搜源码或 ZIP。
4. 在已授权设备上安装并启动**本次普通包**，核对安装/启动结果；对照源代码与包内配置，避免留着上一次 QA 构建产物。
5. 至少两次完整冷启动，覆盖测试器原有的触发窗口：不自动打开测试页、不自动旋转/染白、不自动发测试事件。第一次正常不能排除第二次恢复回调或旧 runId 复跑。随后按用户动作验证网页旋转，保持背景正确，恢复原状态。
6. 清理未参与本次普通构建的旧 QA 导出副本；常用 DerivedData 产物路径不得仍指向 QA 而被下次误打包。可复用同一待交付源码已构建、签名校验并记录哈希的普通 `.app`，不必仅为清理重建。恢复源文件、普通包安装成功与启动成功分别持久记录，即使中途失败也能继续收尾。
7. 关闭本次调试连接和外部驱动；从正确源目录打包并比对。最终分别报告源码/ZIP/手机状态与尚未验证项。

设备不可用时，可以完成源码、归档和构建检查，但“已替换手机包/普通包冷启动通过”保持未验证；不把任务自动延伸为未经用户请求的后台定时跟进。

## 可复用的只读产物检查

```sh
python3 scripts/check_delivery_artifacts.py \
  --project /path/to/authoritative-project \
  --archive /path/to/project.zip \
  --app /path/to/NormalTest.app \
  --exclude Assets/Editor/Integration/DeviceTestBuild.cs \
  --exclude Assets/Editor/Integration/DeviceTestBuild.cs.meta
```

排除项按本项目实际存在且明确不交付的文件给出；示例不是必需文件列表。只接受具体文件路径，不使用 `*.cs` 一类宽泛排除来掩盖资源遗漏。可用 `--forbid-marker YourKnownQAHarness` 添加本项目自建自动运行测试器的类/符号。默认扫描本参考实现中已知的自动测试标识；`Color.white`、普通启动钩子本身不是测试残留，不能一刀切删除合法业务代码。

合法 Editor 回归测试应保留在源码 ZIP 中。要核对其未编入 Player，另做仅 `--app` 的二进制扫描；不要把该类名作为整个源码 ZIP 的禁止标识。

脚本比对 ZIP 与源文件、检查 CRC/路径、扫描已知 QA 标识；`--app` 支持常见 Unity IL2CPP + UnityFramework 布局。返回 0 表示所提供产物的检查通过，1 表示检查失败，2 表示参数/输入不支持。不同布局、加密元数据需另行验证，不算“无残留”。脚本不连接手机、不验证签名/完整编译、不证明未知名称的测试器不存在，也不证明冷启动或后台入库。输出的设备/冷启动/后台验证标志始终为 false；用真实安装和行为证据补齐。

## 完整工程归档与检查器范围

先按实际工程类型选择打包内容。Unity 源工程保留源码、资源与项目配置；已经导出的 Xcode 工程还需完整保留 Xcode 工程/共享 scheme、Unity 数据、生成的 IL2CPP 源码及构建工具、所需静态库、原生 SDK/资源/许可证、配置和可执行安装脚本，不能套用只打包 `Assets/Packages/ProjectSettings` 的清单而漏掉必需文件。只排除已识别的构建/下载缓存、旧备份和用户本机状态，不按所有同名 `build` 目录一律剔除。交付说明注明工程类型、构建号、解压后的实际入口及真机待验证项；脚本根目录按其所在位置解析，避免依赖作者桌面绝对路径。

当前 `check_delivery_artifacts.py` 的源码预期清单仅含 `Assets/Packages/ProjectSettings`，并把 ZIP 符号链接列为需审查。完整工程另含 `ThirdParty` 原生 SDK、许可证、构建辅助文件、文档或原有资源时，可能报 `unexpected_files`；不要为让检查器通过删掉必要交付内容，也不要改写其失败结果。

这种布局另做完整清单比对：从唯一源目录枚举实际交付文件，检查 ZIP 重复/危险路径、CRC、每个普通文件内容哈希；符号链接比较类型和原始链接文本，并验证目标是相对路径、可解析且位于随包 SDK/工程内，目标实体也已打包。保留合法 XCFramework 链接语义，不将目录链接递归展开成重复内容。绝对路径、越界/断链/循环链接仍失败。保留通用检查报告，并用独立报告说明已人工复核的差异及证据，不把 App 二进制扫描通过提升为 ZIP 或真机通过。

## 交付测试包给用户自测

本系列的默认交付形态是：接入完成后构建独立 Bundle ID 的测试包（如 `<正式BundleId>.sdktest`），直接安装到已确认真机，保留给用户自测；不额外跑模拟器，也不要求用户改用正式包。该测试包不是自动 QA 包，但仍是普通运行包：不得包含自动测试器、自动旋转、自动事件或测试网页入口。

- 安装前核对签名身份、Team、Profile 与目标 Bundle ID；安装后单独启动一次并记录启动 UTC、runId、入口请求、`Web active` 或原生回退的实际结果。
- 设备测试按阶段记录实际方向：启动页/Loading、默认网页为 Portrait，回退时恢复原生游戏原方向；有明确不同产品要求时按该要求验收。用户自测项（ATT 弹窗交互、H5 往返、网页安全区/显式旋转、AF/FB 后台收数）保持未验证，不因“app 已安装并启动”升级为通过。
- 报告写明手机实际安装的测试包 Bundle ID、Profile 到期时间、正式包是否安装。正式包可以只导出不安装，但必须明确写出。
- 若任务曾安装自动 QA 包，仍需按上一节换回普通包；用户自测的独立测试包也属于普通包。


只要求工程时交付核验后的源码 ZIP。提供真实绝对路径链接，避免不可见字符或旧版本链接；附关键版本/包名即可，不必再次延伸为发布或 SDK 后台验收。
