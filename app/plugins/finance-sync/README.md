# finance-sync 运行器契约

该模块为“工作数据更新”中的消耗和广告提供在本地执行的代码。公开参数不包含主机路径：`pluginId=finance-sync`，`parameters.mode=consume|ads`；旧的 `dapan` 运行范围仍可使用。

消耗入口支持 `parameters.dates`：逗号分隔的单日或连续日期，最多 31 天。页面默认选择昨天，支持切换单日和日期范围，批量更新继承当前选择。只更新所选日期的消耗/安装及缺失日期行；大盘和消耗日报使用范围的结束日。来源缺少所选日期时返回该产品的问题，不把缺失来源补成零或生成完整日报。未传日期的旧调用保留全部历史同步。广告和独立大盘参数不接受 `dates`。

代码来自参考附件 `消耗-sync-migration.zip` 的 Python 源文件。原始文件哈希与打包调整见 `provenance.json`。`scripts/` 只包含代码，不包含凭据、规则快照、结果、SQLite 或其他运行时文件。原业务资源标识仍在代码常量中；资源标识不是登录授权。部署前必须核对规则库和目标资源的归属。

入口优先级为：本机 `PARTNER_FINANCE_SCRIPT_PATH` → 旧显式 `scriptPath` → 冻结插件的 `scripts/run_consume.py` → 应用内置 `scripts/run_consume.py`。已配置但无效的路径会失败。内置 manifest 不再声明 `scriptPath`；旧 manifest/直接调用 runner 仍能传入该字段。

用户电脑需要 Python 3.8+（纯标准库），并明确配置可执行的 `SYNC_LARK_CLI`，或 Bash launcher `FEISHU_TEAM_RUNNER`。后者的调用形式为 `/bin/bash <launcher> cli <args...>`。优先选择 `SYNC_LARK_CLI`；无效的显式配置不会转用另一个账号。包内所有 API、卡片和审计中转模块共用这一选择机制，不再搜索某台机器的桌面插件路径。身份与权限由部署环境提供，本地文件存在不能证明授权可用。

`check` 只验证配置、必需文件、解释器和 Python/Bash 语法，不导入业务模块、不执行 CLI、不读取飞书、不生成规则快照。缺少部署依赖返回失败；未验证的授权明确显示为待验证。

实际执行时，runner 将纯 `.py` 文件复制到 `<taskDirectory>/finance/run-*`，记录代码 SHA-256，再在该目录启动。脚本使用 `__file__` 或当前工作目录定位状态，两者均落在本轮目录。不会复制源安装的快照、数据库、结果或凭据。子进程 `SYNC_LOG_DB` 固定为本轮数据库，`SYNC_RUN_ID` 清空；`SYNC_MACHINE` 保留部署名称/主机名前缀并附加本轮目录名，避免独立数据库中同秒运行在中转去重时撞键。本地 App 进程的环境变量不变。

正式消耗同步与独立大盘操作先明确执行 `bootstrap_rules.py`：从四张规则表只读获取完整快照。准备失败就停止，不启动同步。消耗预演只刷新消耗段，不运行大盘；广告入口只读获取广告规则。消耗刷新保留广告段，广告刷新保留消耗段，快照不跨任务共享。

业务顺序和口径沿用原代码：TopOn 先完成，再运行 MAX/AdMob；`serial` 令三者按顺序串行。叠加公式、生效起始日、消耗归属及大盘重复日期取最后一行的规则不变。消耗子进程失败时停止后续大盘、日报和中转。

预演始终传 `--dry`，不生成正式日报，并禁止审计中转。预演仍写本地快照、结果 JSON、SQLite 的运行/步骤记录；不会把计划变更落入正式规则、单元格、大盘或卡片审计。正式运行不发送消息，中转默认关闭。`sendCard=true` 已停用并明确拒绝；`pushAudit` 仅消耗/广告可用；`serial` 仅广告可用。

结果验证继续绑定本轮入口、运行 ID、审计和新结果文件：拒绝旧结果、并发归属不明、0/0、规则缺项、失败步骤和审计不一致。广告未推中转且逐项证据完整时可确认成功。大盘已保存逐项写入回执，但没有完整回读核验，消耗/大盘整体仍保持“待核对”；中转接收确认不足时也不会由退出码推断成功。

`run_all.py`、自动手动触发器、原 bootstrap/selfcheck 均未打包或作为 runner 入口。`sync_daily_summary.py [local] [--consume]` 只读表格并生成 `finance-report.json`，不调用消息或看板接口。正式消耗同步在大盘和日期校验通过后调用它，旧 `--no-card` 保留兼容但不影响本地日报生成。JSON 包含运行 ID、生成时间和数据日；server 核验文件属于本轮后，分别返回可复制的消耗日报与执行结果。正式日报使用 `--from-run` 读取本轮已确认的大盘值，部分失败只影响统计范围，失败产品及原因单独列在执行结果。广告入口仅返回本轮规则核验摘要。runner 的检查和预演均不会调用日报脚本。详细部署说明见 `docs/data-updates-deployment.md`。
